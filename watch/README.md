# Wear OS companion

This module shares the phone application ID and must be signed with the same certificate. Install it on the watch, not over the phone APK. Recognition and resources remain on the phone; this APK contains no model or index.

The round, scrollable native UI and Tile provide start/pause, effective phone/watch microphone selection and history. Audio-saving, timing-debug and result-update interval controls are available in the application. Settings are explicit revisioned commands, acknowledged by the phone; lost messages retry the same request ID at most three times. A stale revision is reconciled from the returned state and shown as an error rather than silently overriding a newer setting. Restart/reconnect queries effective state instead of replaying obsolete desired values.

The watch microphone starts only after a visible interaction grants permission. Its foreground service waits up to 60 seconds for effective `listening=true`, `microphone=watch`, `ready=true` before opening a nearby Data Layer channel. It never silently switches sources or queues cold-start audio. Each new channel has a fresh UUID and sequence zero, fixed 4000-sample PCM frames via `AudioWire`, and no audio replay after disconnection. Buffering is capped at four half-second blocks; slow transport fails visibly. Supported-rate capture falls back from 8 kHz to 44.1/48 kHz with a streaming anti-alias FIR resampler. The ongoing notification stops capture and requests phone pause.

The LONG_TEXT complication caches the orchestra as primary text and song as title. Changed text or stale status requests a complication update. Unchanged text renews at five-minute intervals while fresh phone states arrive; data expires ten minutes after its phone timestamp so a long song does not vanish after thirty seconds. Without a disconnection callback or a platform refresh, stale face data can remain visible until that bounded expiry. Wear OS may throttle these requests; the configured result-update interval is not a guarantee of face refresh latency. Cached disconnected text is marked with `?`. The separate `:watchface` package is an actual resource-only WFF face, not a full-screen app substitute.

Actual Xiaomi Watch 2 microphone quality, Data Layer latency, lock-screen startup and battery life require paired-device testing. Emulator UI/resampler checks do not establish these properties.

The optional 0.5.1 full-screen display opens with ⛶ in the companion or Tile. Orchestra/song pushes render directly while interactive; AndroidX ambient callbacks show a monochrome display with a small clock while asleep. An Ongoing Activity supports retention past the return timeout on Wear OS 5+; older versions may still apply their return-to-face setting. Back or Close display ends only this display session, not recognition or microphone capture. See [TESTING.md](TESTING.md) for validation and physical-device limits.

With phone/watch 0.5.5, tap the current orchestra in controls or the full-screen display to reset recognition with the newest two seconds of captured audio. No extra watch button is added. Reset preserves saved history and the microphone selection; exact command retries are deduplicated on the phone. Paused recognition is not started.

Watch 0.5.7 loads `src/main/assets/orchestra-keywords.json` once for display-only name preferences. The two-line name view measures real font metrics, emphasizes shorter names/approved aliases, and retains the original style when no safe fitting hint exists. Multiword surnames are allowed; whole qualified names do not receive forced emphasis. LJD is appended for La Juan D’Arienzo. No phone/catalog/protocol update is required.
