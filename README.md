# TangoWiz Android

Install the small APK from [Releases](https://github.com/mstsirkin/tangowiz-android/releases/latest). On first launch, a dedicated setup screen checks the resource manifest and shows the download size before you download the model and catalog. Recognition controls appear only after resources are fully verified. Setup shows download/verification progress, retry and app-update actions; completion opens recognition without starting the microphone. Setup displays the current ZIP size before downloading. Recognition then works offline, without an account or server. Later launches go directly to recognition when valid resources are installed. Download notifications reopen setup/progress; Update opens setup separately, and Back leaves an existing working library usable.

The overflow menu opens the separate setup screen for **Update**, and contains **Automatic update checks**. Automatic checks are off by default; turning them on allows a small manifest check when opening the app, at most once a day. A check never starts a large download. Manual Update works regardless of that toggle. Previously requested interrupted downloads resume after reopening the app. Missing or incompatible resource formats offer an app update; ordinary network failures offer retry and preserve installed resources.

Resources use the numbered format URL `https://github.com/mstsirkin/tangowiz-android/releases/download/resources-v2/manifest.json`. Four fixed HTTP ranges download one SHA-keyed archive with durable range checkpoints and aggregate progress. Servers that ignore ranges fall back to a single resumable stream. The archive SHA256, ZIP CRC32, allowlisted entry names/sizes/SHA256 values, actual native catalog structure and TFLite shapes are checked before an atomic switch to immutable local files. Failed downloads or validation retain the previous working bundle. Resource updates pause identification and release the old engine safely; tap Resume afterward. Android data-sync timeouts preserve download checkpoints.

The phone keeps only the active bundle after validated activation and release of the old engine handles; the downloaded ZIP is then deleted. Old ZIPs and matching versioned manifests remain on GitHub for rollback by redownload; there is no offline phone backup by default.

The application source repository does not contain the recognition catalog, model, collection, training data, or data-generation pipelines. They are not needed to build the APK. Kotlin UI, native CPU recognition, pinned TensorFlow Lite dependencies and build tooling are here; resource releases are published separately. The current snapshot contains 49,500 references and 17,618,697 fingerprint windows.

Build with Java 17, Android SDK 35, NDK 27.0.12077973, CMake 3.22.1 and the bundled Gradle wrapper:

```
export ANDROID_HOME=/path/to/android-sdk
./build_apk.sh
```

Gradle downloads the pinned TensorFlow Lite dependencies. Generated large local asset files are explicitly excluded from APK packaging, even if present in a developer checkout. The build aligns/signs with a local Android development key; keep the same key to install upgrades and never publish its private file. No resource extraction from an older APK is required.

The main screen uses icons for play/pause, saved microphone audio, timing debug, diagnostics share and the overflow menu. Ongoing notification controls are Pause/Resume, Open and Exit. Pause stops capture, audio saving, inference and the wake lock while retaining the primary model/index for quick resume. Exit closes resources and finishes the app task, including in the background. Android can reclaim a service under memory pressure. Microphone and notification permissions are required for identification. Audio, fingerprints, history and timing remain local until manual share.

Live candidate-card percentages are twice the existing integer similarity percentage, capped at 100%; for example, 30 becomes 60 and 70 becomes 100. This is a presentation scale, not a calibrated probability. History rows retain their original percentages. Raw scores, saved history values, candidate ranking, and recognition thresholds remain unchanged. The continuous baseline speed stream is supplemented by bounded background speed checks. The compact PQ reconstructed reranker is not bit-identical to the server float-vector reranker. Physical phone performance must be measured separately from emulator tests.

The neural adaptation is GPL-3.0, the scanner MIT, and TensorFlow Lite has its dependency notices. App source is GPL-3.0; separate dependency and data licenses remain as documented in the notices.

Candidate copies are combined using verified recording groups, precomputed in format 2 and checked from reference-to-reference fingerprints for legacy format 1, never merely because titles match. Complementary orchestra, title, singer and date credits are combined. Equivalent accents/case, corroborated title credit suffixes and compatible year/date precision do not create false conflicts; genuinely different labels are shown together with `?`. Consecutive history detections follow recording-group/source aliases within the same session, while later repeats remain separate. Append-only history and per-session raw match results remain available in diagnostic exports.

Version 0.4 accepts installed bundles and interrupted downloads from resource formats 1 and 2. New update checks prefer `resources-v2/manifest.json`; existing format 1 resources remain usable offline without migration or a forced download. The private storage directory retains its historical name for compatibility. Imports verify that a format 1 manifest contains `TWIDX001` and a format 2 manifest contains `TWIDX002` before activation. Internal duplicate-group keys are runtime details, not persisted history fields; history retains source IDs and combined metadata.

**Export debug info** is in the overflow menu. It opens a separate screen immediately, scans the saved sessions, and shows file count, total bytes and byte progress while preparing one ZIP. Recognition can continue. When ready, use the standard share icon or the download/save icon; Save ZIP opens Android’s folder/filename picker and provides a retrieval path independent of the sharing chooser. Completed exports can be reopened after Activity/process recreation. Interrupted work shows a retry message; export cancellation or failure does not delete recordings or logs.

The current guesses show one row per unambiguous orchestra, using its strongest recording score. Compatible credits fill blanks; differing song, singer or date claims remain alternatives marked `?`. This is presentation only: native recording groups, raw match logs, and history identity stay anchored to the strongest recording. Different songs by one orchestra remain separate history entries. History stores compact contributor IDs/scores beside combined metadata; full per-source credits remain in raw match diagnostics. Unknown or conflicting orchestra labels and modern `La Juan D’Arienzo` are kept separate. Long cards and history rows are bounded; tap a row to read all labels. An uncertainty marker stays visible before truncated alternatives, and full labels remain accessible.

**Clear older history and recordings** is in the overflow menu, with a confirmation before deletion. It removes completed sessions’ audio, fingerprints, result/timing logs and history entries, while retaining the active recognition session in full, including earlier files from that session when recording/debugging was toggled. Capture and recognition continue. Session protection ends only after capture and queued writes close. Cleanup runs off the UI thread and reports freed space or incomplete deletion. Existing exported ZIPs, the model/catalog and settings are retained. An active export must finish before cleanup can proceed.

The optional Wear OS companion, Tile and actual system watch face are described in [WATCH.md](WATCH.md). Recognition stays on the phone. Watch microphone selection and controls are synchronized through the Wear OS Data Layer, with explicit acknowledgements and bounded live audio buffers.

Phone 0.5.2 immediately pushes transitions into the existing strong result state to the watch, bypassing its normal update interval and marking the persistent DataItem urgent. Watch 0.5.1 and face 0.5.0 remain compatible. Confidence values and thresholds are unchanged; Wear OS still controls ambient/complication redraws.

Phone 0.5.3 requests a 4 MiB TCP receive buffer before each library-download connection connects, preserving larger existing buffers. It keeps four independent HTTP/1.1 range streams. Android can cap the request; a capped or unsupported request uses a fresh socket with automatic receive sizing, avoiding a small fixed-buffer limit. Effective buffer decisions appear under `TangoDownload` in Android logs. This is a throughput tuning request, not a measured phone-speed guarantee. TLS certificate/hostname checks, resource hashes, saved checkpoints and installed libraries remain in place.

Downloader tuning points: `DownloadSocketFactory.REQUESTED_RECEIVE_BYTES` (currently 4 MiB; constructor value 0 means automatic), four parallel ranges, 256 KiB application reads, durable checkpoints every 4 MiB, 20-second connection timeout and 30-second read timeout. Changing socket memory does not change the recognition model, catalog or matching scores. Tests cover pre-connect configuration, OS caps, cancellation/retry, range redirects, saved-checkpoint recovery and actual HTTPS range downloads on Android. Physical-phone throughput still needs measurement.

Phone 0.5.4 adds separate **Pause** and **Cancel download** controls. Pause stops transfers and saves received bytes for Resume. Cancel waits for all writers to stop, then removes temporary archives, checkpoints, pending offers and extraction staging; the installed library stays available. A blocked body read has a 45-second watchdog (the existing 30-second read timeout can fire sooner). Each failed range reconnects independently from its saved position while healthy streams continue; five consecutive attempts without progress stop with a retry action.

**Check app update** checks published phone APK releases, including the current prerelease phone series, and offers a download button only for a newer version. The button opens the APK URL using Android’s default browser/link handler; no browser package is forced. This check is independent of the library download.
